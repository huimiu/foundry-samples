# Claude Agent SDK Agent (Invocations Protocol)

A getting-started Bring Your Own hosted agent using the [Claude Agent SDK](https://pypi.org/project/claude-agent-sdk/) with Microsoft Foundry authentication and the [azure-ai-agentserver-invocations](https://pypi.org/project/azure-ai-agentserver-invocations/) protocol. It reads a plain-text prompt and streams Claude SDK messages as Server-Sent Events (SSE).

## How It Works

1. [main.py](main.py) reads `FOUNDRY_PROJECT_ENDPOINT`, derives `ANTHROPIC_FOUNDRY_BASE_URL` from the Foundry account host, and relies on the Foundry Claude integration (`CLAUDE_CODE_USE_FOUNDRY=1`)
2. `InvocationAgentServerHost` exposes `POST /invocations`
3. The invocation handler reads the request body as a non-empty plain-text string; it does not parse a JSON field for the prompt
4. The handler calls `claude_agent_sdk.query()` with `ClaudeAgentOptions`, `permission_mode="dontAsk"`, `include_partial_messages=True`, and the `ANTHROPIC_MODEL` declared in `agent.yaml`
5. Each SDK message is serialized with `dataclasses.asdict()` and yielded as an SSE `data:` event
6. The included `.claude/skills/joke/SKILL.md` skill asks Claude to answer joke requests in a friendly pirate tone

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `FOUNDRY_PROJECT_ENDPOINT` | Yes | Azure AI Foundry project endpoint URL. Auto-injected when hosted — only needed locally |
| `CLAUDE_CODE_USE_FOUNDRY` | Yes | Set to `1` in `agent.yaml` and `.env.example` to enable the Foundry integration path in the Claude Agent SDK |
| `ANTHROPIC_MODEL` | Yes | Claude model name used at startup. `agent.yaml` sets `claude-opus-4-7` |
| `ANTHROPIC_FOUNDRY_BASE_URL` | No | Generated by [main.py](main.py) from `FOUNDRY_PROJECT_ENDPOINT` as `https://<account>.services.ai.azure.com/anthropic` |
| `APPLICATIONINSIGHTS_CONNECTION_STRING` | No | Application Insights connection string. Auto-injected when hosted — only needed locally for telemetry |

This sample uses Foundry authentication and does not require an Anthropic API key.

## Running Locally

### Prerequisites

- Python 3.10+
- Azure credentials available to the Claude SDK/Foundry client (for example, `az login` and `azd auth login`)
- An Azure AI Foundry account/project with access to the Claude model named by `ANTHROPIC_MODEL`

### Using `azd` (Recommended)

Create a local `.env` file from the sample template and fill in the required values:

```bash
cp .env.example .env  # skip if .env already exists
# Edit .env — see Environment Variables above
```

The sample loads `.env` automatically when running locally. Next, start the agent locally with the `run` command:

```bash
azd ai agent run
```

The agent starts on `http://localhost:8088/`.

**Local:**

**Bash:**
```bash

```

**PowerShell:**
```powershell
azd ai agent invoke --local "List the main Python files in this folder."
```

**Test with curl:**

```bash
curl -sS -N -X POST http://localhost:8088/invocations \
  -H "Content-Type: text/plain" \
  -d "List the main Python files in this folder."
```

**SSE Event Format:**

Each Claude SDK message is streamed as `asdict(message)`:

```
data: {"type": "assistant", "...": "..."}

data: {"type": "result", "...": "..."}
```

## Adding Skills

Claude Agent SDK skills live under `.claude/skills/`. This sample includes a `joke` skill:

```
.claude/
└── skills/
    └── joke/
        └── SKILL.md
```

The skill tells the agent to answer joke requests in a friendly pirate tone. Add more skills by creating additional subdirectories under `.claude/skills/` with their own `SKILL.md` files.

## RBAC Configuration After Deployment

After deploying with the section below, assign **Foundry User** at the Foundry account scope to the hosted agent's runtime identity. Without this account-level role, the agent can initialize but Claude model inference may fail with `401 Unauthorized`.

1. Get the agent runtime principal ID:

   ```bash
   azd ai agent show
   ```

   Use the `instance_identity.principal_id` value from the output.

2. Assign **Foundry User** at the account scope, replacing the placeholders:

   **Bash:**
   ```bash
   az role assignment create \
     --assignee-object-id <PRINCIPAL_ID> \
     --assignee-principal-type ServicePrincipal \
     --role "Foundry User" \
     --scope /subscriptions/<SUBSCRIPTION_ID>/resourceGroups/<RESOURCE_GROUP>/providers/Microsoft.CognitiveServices/accounts/<ACCOUNT_NAME>
   ```

   **PowerShell:**
   ```powershell
   az role assignment create --assignee-object-id <PRINCIPAL_ID> --assignee-principal-type ServicePrincipal --role "Foundry User" --scope "/subscriptions/<SUBSCRIPTION_ID>/resourceGroups/<RESOURCE_GROUP>/providers/Microsoft.CognitiveServices/accounts/<ACCOUNT_NAME>"
   ```

3. Verify the assignment and wait 2–5 minutes for propagation:

   ```bash
   az role assignment list --assignee-object-id <PRINCIPAL_ID> --all -o table
   ```

## Troubleshooting

### Images built on Apple Silicon or other ARM64 machines do not work on our service

We **recommend deploying with `azd deploy`**, which uses ACR remote build and always produces images with the correct architecture.

If you choose to **build locally**, and your machine is **not `linux/amd64`** (for example, an Apple Silicon Mac), the image will **not be compatible with our service**, causing runtime failures.

**Fix for local builds:**

```bash
docker build --platform=linux/amd64 -t image .
```

This forces the image to be built for the required `amd64` architecture.

### Claude model calls fail with 401 Unauthorized

Confirm the hosted agent runtime identity has **Foundry User** at the Foundry account scope, not only at the project scope. Re-run `azd ai agent show`, verify the principal ID, and check role assignments with `az role assignment list --assignee-object-id <PRINCIPAL_ID> --all -o table`.
